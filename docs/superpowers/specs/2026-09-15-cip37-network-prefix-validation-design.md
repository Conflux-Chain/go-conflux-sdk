# CIP-37 网络前缀严格校验设计

## 背景

`types/cfxaddress/network_type.go` 当前使用 `strconv.ParseUint(..., 0, 32)` 解析 `netN` 中的网络 ID。基数 `0` 会接受十六进制，并把带前导零的字符串按八进制解释；同时，现有实现未拒绝 CIP-37 保留的网络 ID `1` 和 `1029`。因此，解码器会接受不符合 CIP-37 的网络前缀，并可能为同一网络和账户产生多个字符串表示。

CIP-37 将网络前缀限定为：

- `cfx`，对应主网网络 ID `1029`；
- `cfxtest`，对应测试网网络 ID `1`；
- `netN`，用于其他网络，且 `N != 1, 1029`。

CIP-37 还要求解码时按照上述定义验证网络前缀。本修复据此采用严格拒绝策略，不对非法前缀做静默规范化。

## 目标行为

`getIDWhenBeginWithNet` 仅接受 `net` 后紧跟网络 ID 的规范十进制表示：

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `net0` | 接受为 `0` | 当前 SDK 支持的规范十进制形式 |
| `net17` | 接受为 `17` | 合法私有网络前缀 |
| `net1` | 拒绝 | 必须使用 `cfxtest` |
| `net1029` | 拒绝 | 必须使用 `cfx` |
| `net017` | 拒绝 | 带前导零，不是唯一规范表示 |
| `net0x405` | 拒绝 | 不是十进制表示 |
| `net` | 拒绝 | 缺少网络 ID |
| 超出 `uint32` 的值 | 拒绝 | SDK 网络 ID 类型为 `uint32` |

## 实现设计

修改范围限定在 `types/cfxaddress/network_type.go`：

1. 保留现有的 `net` 前缀检查。
2. 使用基数 `10`、位宽 `32` 解析后缀。
3. 使用 `strconv.FormatUint(parsed, 10)` 重新生成规范后缀，并与原后缀比较；不一致时拒绝，从而排除前导零和其他非规范表示。
4. 解析结果为 `1` 或 `1029` 时拒绝，要求调用方分别使用 `cfxtest` 或 `cfx`。
5. `NewNetworkType` 和 `NetworkType.ToNetworkID` 继续复用该函数，因此所有公开入口获得一致校验。

不修改 `Address.Equals`。问题根因是解码器接受非法网络前缀；在输入边界拒绝非法形式后，无需改变地址相等语义或现有数据结构。

## 错误处理

非法前缀继续通过现有函数签名返回错误，不引入新的导出错误类型。测试只断言是否返回错误，不绑定具体错误文本，以避免无必要的兼容约束。

## 测试设计

新增表驱动单元测试，直接覆盖 `NewNetworkType` 和 `ToNetworkID` 所依赖的网络前缀解析行为：

- 合法：`cfx`、`cfxtest`、`net0`、`net17`、`net4294967295`；
- 非法保留值：`net1`、`net1029`；
- 非规范数字：`net00`、`net017`、`net0x405`；
- 格式错误：`net`、非 `net` 前缀、负数；
- 范围错误：`net4294967296`。

另增加地址解码回归测试：使用公开校验和计算能力构造校验和正确但网络前缀非法的完整地址，确认 `NewFromBase32` 在网络前缀校验阶段拒绝该输入。

执行顺序遵循 TDD：先运行新增测试并确认其因当前宽松解析而失败，再修改生产代码，最后运行包级测试和仓库全量测试。

## 非目标

- 不改变大小写处理、地址类型选项或校验和算法。
- 不改变 `NewNetworkTypeByID` 的编码结果。
- 不重构 `Address.Equals`。
- 不处理与 CIP-37 网络前缀无关的地址解析行为。
